# Spec: S2b1 HumanThink 聊天框（interactive 长会话）

- **topic**：atd-s2b1-humanthink
- **状态**：v7 业务语言版（按用户指示收束技术描述；技术实现细节由 impl 阶段文档承载，r1-r5 审查报告保留全部技术事实锚点）
- **日期**：2026-09-25（v1-v6 审查收敛 94 分后，应用户要求转为业务描述形态）
- **上游**：Epic §4.3/§4.4/§9；已定决策：聊天历史由 ATD 自己存一份；聊天走常驻的 agent 服务
- **用户已拍板**：① 派单执行（task 模式）切共享服务拆成独立后续 Story ② 会话记录永久保存 ③ agent 服务的数据与自用 opencode 混在一起可以接受，ATD 只要能正常调用 worker 即可

## 背景

ATD 目前只有工单：人提需求单 → agent 干活 → 卡点回来找人。但很多事发生在「提单」之前——想法没成形、需求要聊清楚、方案要试探。HumanThink 聊天框就是补这一段的：**像跟一位坐在你项目里的同事聊天**。你选一位助手（worker）和它负责的项目群（workspace），用自然语言讨论；它看得见项目文件、答得了问题、帮你把需求聊成 spec。下一阶段（S2b2）会把「聊出来的 spec」一键变成工单。

Epic 最终验收的场景就是：在一个真实项目上，通过聊天完成一次小需求的「沟通→spec」，全程不打开终端。

## 范围

**做**（用户得到什么）：

1. **聊天页**：会话列表（按 workspace 归组、可搜索）+ 聊天窗——回复逐字流式出现、助手思考过程折叠展示、工具动作以卡片展示、随时点停止
2. **新建会话**：选 worker × workspace 开聊
3. **行为边界**（本 Story 的核心价值）：助手只能看所属 workspace 声明的仓；越界触碰一律系统级拒绝；敏感动作（跑命令/改文件）先请示你
4. **历史**：全部对话记录存 ATD 自己的库；删除会话=从列表移除、历史仍可查
5. **恢复**：ATD 或 agent 服务重启后，会话无损续聊
6. **worker 接入门槛**：worker 以声明方式登记「我提供聊天能力」及服务启动方式（与现有派单模式同一套声明风格）

**不做**：聊完自动提单（S2b2）；派单模式切换共享服务（独立后续 Story）；多用户/登录；全文搜索引擎、会话导出、一个会话里混多个 worker。

## 验收标准（用户可逐条验证）

1. **会聊**：聊天页选 opencode × workspace → 发消息 → 回复逐字出现；思考过程折叠可见；调工具时有动作卡片
2. **不丢话**：昨天的会话今天打开内容完整；重启 ATD 和 agent 服务后继续聊，不丢不重
3. **不干扰**：你日常自用的 opencode（终端/网页版）不受 ATD 聊天功能任何影响
4. **有边界**：让它读 workspace 外的文件 → 直接做不到（系统拒绝，不会拿来问你）；让它跑一条命令 → 弹「允许吗」→ 你拒绝 → 它继续对话不卡死；读 workspace 内文件一切正常
5. **可打断**：生成中途点停止 → 立即停，可以接着问下一句
6. **不泄密**：各种密钥/密码只存在于运行中的程序内存，不落进仓库任何文件
7. **不伤旧**：原有工单功能全部照旧（全量测试绿）

## 业务规则

1. **会话归属**：一个会话属于一个 workspace；助手的「工作位置」是该 workspace 的主仓目录
2. **视野**：助手可见范围=workspace 声明的仓（主仓+可读仓）；视野外一律不可见。这是**系统硬约束**，不依赖助手自觉
3. **行为三档**：视野内读=自由；视野外任何触碰=系统直接拒绝；其余动作（跑命令/改文件等）=请示你，**你是最终裁决人**
4. **裁决粒度**：你的批准/拒绝只对当次动作生效；下次敏感动作还会再问（不做「永久记住授权」，保持简单可控）
5. **软删除**：删除的会话从列表消失、历史可查、不能再发消息
6. **断线与恢复**：agent 服务崩溃后 ATD 自动拉起，并补齐中断期间的对话记录；界面以完整文本对齐（中断瞬间的逐字动画不保证重放）
7. **附属关系**：agent 服务是 ATD 的附属进程——ATD 启动则起、关闭则停；起不来时聊天页提示「服务不可用」，**工单功能完全不受影响**
8. **名单时效**：workspace 名单在服务运行期间不变，新接项目需重启 ATD 生效（与既有「改 workspace 配置需重启」一致）
9. **检索**：按会话标题+内容关键字搜索
10. **连接边界**：浏览器只连 ATD，由 ATD 中转与 agent 服务对话（单一安全边界）

## 关键风险（业务可理解）

| 风险 | 应对 |
|---|---|
| 权限规则表达不了「视野」语义 | 动工前先做小规模真机验证（见下节），失败即停下重新评估方案，不硬闯 |
| agent 服务与 opencode 版本演进不兼容 | 锁定版本，升级时专门验证 |
| 服务中断期间体验 | 恢复后以完整文本对齐，宁缺逐字动画不丢内容 |

## 动工前验证（真机小实验，失败即停）

1. **视野规则装得上**：助手的身份与视野规则能被系统正确装载——该拒的拒、该放的放
2. **三档行为真的生效**：视野内自由读、视野外被拒、敏感动作弹请示
3. **请示流程走得通**：弹卡→批准/拒绝→会话继续，来回可靠
